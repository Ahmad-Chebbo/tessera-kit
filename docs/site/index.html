A Laravel kit you assemble from modules.

Start with sign-in, users and roles. Add sales, inventory, expenses or staff scheduling as Composer packages, and build your own modules the same way.

Install Tessera Browse the modules
  • Laravel 13, PHP 8.4, Inertia, Vue 3 and Tailwind 4
  • English and Arabic, right-to-left included
  • Modules work on their own or with the others
Pick the modules you need

Built in layers, each one optional

Each layer is its own Composer package. Install only the ones you need, and the layers above it stay out of your project.

app/Modules

Your own modules. They sit in the project, load exactly like the packaged ones, and can be packaged for other projects later.

tessera/tessera-<module>

Eleven feature modules: catalog, inventory, customers, orders, pos, discounts, expenses, reports, exports, shifts and attendance. A twelfth, sales, installs the orders and the till together.

tessera/tessera-saas

Plans, subscriptions and the screens a platform admin uses to create tenants. Add it only when one install serves many businesses.

tessera/tessera-tenant

The business: its branches, stock locations, currencies and settings. One tenant for a single business, many with the SaaS layer. The feature modules keep their data here.

tessera/tessera-base

Sign-in, registration, password reset, profile, API tokens, users, roles and permissions. Has no tenant, branch or plan of its own.

tessera/tessera-engine

Finds, orders and boots modules, and gives you module:make, module:add, module:check and module:package. Works in any Laravel 13 app.

@tessera/tessera-ui

Vue 3 components, charts, composables and the theme. Installed with bun or npm, and usable on its own.

Modules talk to each other through small contracts, never through each other's controllers. Customers show order history only when Orders is installed, and the profit report subtracts expenses only when Expenses is installed.

What you get

Modules that do not break each other

A module declares what it requires and everything else goes through a contract with a safe default. module:check fails the build when a module imports one it did not declare.

Roles and permissions that follow the modules

Each module declares its permissions and the roles that get them by default. Install a module, run modules:sync, and the role page lists the new permissions.

One business or many

A single business gets one tenant, made for you with a main branch, and the roles are shared. With the SaaS layer every tenant has its own users, roles, branches, stock and settings, and a platform admin creates them and assigns plans. saas:install turns the business you already run into the first tenant.

Plans that switch features on and off

A plan lists the modules a tenant may use and its limits, such as the number of users. Pages, menus and permissions of a module the plan leaves out disappear.

Branches and stock locations

Staff see their own branch, managers with the right permission see all of them, and every report can be narrowed to one branch.

A till that works offline

The point of sale queues sales while the connection is down and syncs them later without double-charging, with weighed goods, held orders, receipts and cash-drawer shifts.

Reports and exports

A dashboard, sales, item and profit reports, and Excel or PDF exports in English or Arabic. Large exports run in the background and wait on an Exports page.

English, Arabic and right-to-left

Every screen has both languages and flips direction with one toggle. Modules ship their own translations, and the checker flags missing keys.

A JSON API from the same code

Modules add API routes under /api/v1, signed in with Sanctum tokens. Set MODULES_LAYERS=api to run without any web pages.

Settings you can override per project

The engine, the Team module, the currencies and any module with a config file can be published to config/ with vendor:publish --tag=tessera-config.

Install

Pick a starting point. Both starters are a normal Laravel project that you own and edit.

Tenants, branches, plans and everything under them. The first account is the platform admin who creates tenants.

  1. Create the project

    composer create-project tessera/tessera-starter shop \
  --repository-url=https://tessera-kit.github.io/tessera-kit
cd shop
bun install

  2. Set up the database and seed it

    # set DB_* in .env if migrations did not run, then
php artisan migrate
php artisan db:seed

    Sign in with admin@app.com and password, and change the password.

  3. Add modules and build the frontend

    php artisan module:add sales
php artisan module:add expenses
bun run build   # or: bun run dev

Sign-in, users, roles and permissions, with no tenants or plans. A good base for an internal tool or an admin panel. Add a module such as catalog and it becomes a single-business app.

  1. Create the project

    composer create-project tessera/tessera-fresh app \
  --repository-url=https://tessera-kit.github.io/tessera-kit
cd app
bun install

  2. Seed the roles and the first account

    php artisan migrate
php artisan db:seed
bun run build

    Sign in with admin@app.com and password. The account is an Owner and holds every permission, so it can manage users and roles straight away.

  3. Turn on more when you want it

    Employee profiles and the activity log are built in but off. Set TEAM_EMPLOYEE_PROFILES=true and TEAM_ACTIVITY_LOG=true, or publish config/team.php.

Use the engine alone in a Laravel 13 project you already have, or add the base for sign-in, users and roles.

  1. Add the engine

    composer config repositories.tessera composer https://tessera-kit.github.io/tessera-kit
composer require tessera/tessera-engine

    Laravel finds the service provider by itself. Modules in app/Modules and Composer packages that declare one are loaded from now on.

  2. Add users and roles if you need them

    composer require tessera/tessera-base
php artisan migrate
php artisan modules:sync

  3. Add the interface kit and a module

    bun add github:Tessera-kit/tessera-ui
php artisan module:add expenses

    The first module you add installs tessera-tenant as well, because modules keep their data per tenant. A project with one business gets one tenant, made for you.

    The starters also include the page shell (sidebar, language and theme toggles) that modules expect. Copy resources/js and vite.modules.js from a starter if you add pages to an existing app.

Start as one business, with no plans and no platform admin. When one install has to serve several businesses, add the SaaS package. The business you already run becomes the first tenant and keeps working.

  1. Add the SaaS package

    composer require tessera/tessera-saas
php artisan migrate

  2. Convert the business and create the platform admin

    php artisan saas:install --admin-email=you@example.com

    The command gives the business its own copy of the roles and moves its users onto them, subscribes it to a plan with every installed module, and creates the platform admin outside every tenant. A password is made and shown once. Running it again changes nothing that is already done.

  3. Sign in as the platform admin

    Only the Admin role can open the Tenants and Plans pages. From there you create more tenants, each with its own owner, branches and plan.

What people build with it

The same pieces fit very different projects. Each example lists what to install.

A shop or small chain with a till

Sell at the counter on a tablet, keep stock per branch, track customers who buy on credit, and see the day's profit. Cashiers see only the till; managers see the rest.

  • sales
  • reports
  • expenses
  • discounts
composer create-project tessera/tessera-starter shop
php artisan module:add sales
php artisan module:add reports
php artisan module:add expenses

The back office of one business

Products, stock, customers and expenses for a shop, a clinic or a workshop, with no plans and no other tenants. People sign in, an owner sets up the branches and decides what each role may do.

  • fresh starter
  • catalog
  • inventory
  • expenses
composer create-project tessera/tessera-fresh shop
php artisan module:add catalog
php artisan module:add inventory
php artisan module:add expenses

Start with one business, grow into a platform

Build the app for the first customer with no plans and no extra tables to explain. When the second customer arrives, add the SaaS package and turn the first customer into tenant number one. Nothing is rebuilt and no data moves.

  • fresh starter
  • tessera-saas
  • saas:install
composer require tessera/tessera-saas
php artisan migrate
php artisan saas:install --admin-email=you@example.com

Software that serves many businesses

One install, many customers. Each tenant gets its own data, users, branches and plan, and you decide which modules and how many users each plan includes.

A module you sell or reuse

Write a module in one project, package it, and install it in the next. Packages keep their namespace and list their provider, so Tessera finds them with no setup.

  • module:make
  • module:package
php artisan module:make Invoices --requires=sales
php artisan module:package invoices

Write your own module

A module is a folder with a service provider. Routes, migrations, translations, Vue pages and config load from the usual places, and the provider says what the module adds to the menu, the permissions and the plans.

Need to change a module you installed? module:publish catalog takes it into your project to edit its models, migrations and pages, and module:publish catalog --pages copies only the screens, so the module keeps updating while your pages replace its own.

module:make creates the folder with a controller, a page, English and Arabic texts and a passing test. module:check keeps it portable.

class InvoicesServiceProvider extends ModuleServiceProvider
{
    public function manifest(): ModuleManifest
    {
        return new ModuleManifest(
            key: 'invoices',
            name: 'Invoices',
            requires: ['sales'],
        );
    }

    public function menu(): array
    {
        return [new MenuItem('sales', 'invoices.nav',
            'invoices.index', 'file-text', 'view invoices')];
    }
}

Good to know

What it needs
PHP 8.4, Laravel 13, Composer and bun (or npm). Any database Laravel supports; SQLite works for trying it out.
Moving from an earlier version
Version 3 renamed company to tenant and split the tenant package from the SaaS one. The migrations rename the tables, columns and permissions of an existing database. The README lists the steps for your own code.
One business or many
Every module keeps a tenant on its data. Without the SaaS package that is a single tenant, made on first use, so you never see it. With it, each tenant is a separate business with its own users, roles and plan.
You own the app
The starters are ordinary projects. The packages update through Composer, and the files in your project stay yours.
Where to report problems
Every package is a read-only copy of a folder in the main repository. Open issues and pull requests on tessera-kit.
